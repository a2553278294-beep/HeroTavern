一、概述
模拟经营系统包括时间流逝、调酒、悬赏、日常经营四个子系统。悬赏是主要收入来源之一，与酒水付费一并进入每日 0:00 结算；张贴与完成规则见《悬赏系统需求案》。NPC 交易本篇只定入口，玩法规则见交易子案。调酒见《调酒系统需求案》。
进店、点哪一杯、是否再点、何时离店，见角色系统。本篇管可售份数、收费时点、酒单、时间、结算与失败。

结算
图中40%成本为占位数据，改为60%
每天 0:00，在主界面余额位置向下弹出分栏。不设确认按钮。弹出 5 秒不可收起，5 秒后自动收起。时间继续流动，天数加一。
分栏展示刚结束的这一营业日：
1. 收入。酒水付费与已入账的悬赏奖励，占第一行，可点开展开。悬赏何时入账见悬赏子案。
2. 支出。营业日成本、酒保工资，占第二行与第三行。
3. 杯数。售出 N 杯 / 未售 M 杯。未售不产生成本。
4. 若本次扣费后余额 < 0，多一行红字「余额不足，游戏结束」。
分栏弹出期间世界不停。这 5 秒内的新点单属于新的一天，不进这张分栏。
四、规则
时间
游戏采用即时制。游戏中每年 365 天，每天 24 小时。
真实秒与游戏小时：
1x 下一营业日 = 240 真实秒。暂停时倍速无效。
暂停入口 = 信息 UI 的暂停图标。玩家可随时暂停。失去酒馆焦点时自动暂停。暂停时时刻停走，制作、饮用停止；尚未点单的客人也不入账。暂停时菜单可操作；酒单仍受准备/营业锁定约束。
酒馆全天 24 小时营业。营业日 = 上一次 0:00 结算之后，到下一次 0:00 结算（含这次结算）。每天 0:00 结算今日流水与成本，弹出分栏，天数加一。
开局：进入游戏即第 1 个营业日开始，先准备再营业，第一次 0:00 才结第 1 天。开局不扣钱。
酒保制作、客人饮用都用游戏内小时计时。饮用固定为 1 游戏小时（1x 下 10 真实秒）。制作时长见酒单上该酒的时长，本篇不写列名。
酒单与可售
准备阶段（0:00 之后到本日营业开始之前）可改上架开关和上架数量。本日经营一开始，酒单锁定，当天不能改。改动只作为下一营业日的可售配置。
点单池：该酒本日上架，且本日剩余可售 > 0。剩余可售在本日营业开始时，按当时酒单上的份数折成今日上限；点单一杯减一。剩余 0 则本日不再被点到。
上架数量为 0 = 今日上限 0 = 今日不会被点到。不必另做一套「关架」逻辑。营业开始后不能关架，因此不存在「今天关架还卖不卖」的分支。
份数不在设定时扣钱。成本按本日实际点单杯数，在 0:00 扣除。
酒保自动执行，玩家不能替客人点单。同一时刻只做一单，多个订单串行。制作时长见酒单。点营业与收费
谁进店、点哪一杯、是否再点、何时离店，见角色系统。本篇只拒绝剩余可售为 0 的酒。
单即入账。客人点成一杯：该酒售价全额计入本日收入，本日该酒售出杯数 +1，剩余可售 −1。不做到付费才入账，因此制作和饮用跨过 0:00 也不会把这杯记到另一天。0:00 不打断已经在做、在喝的单，只是这杯钱已经记在点单那天。
结算分栏弹出的 5 秒内仍可点单；这些点单计入新的一天。
单份成本 = 向下取整（该酒售价 × 60%）G。当日成本 = 各酒当日点单杯数 × 单份成本。未售出份数不产生成本。
调酒
调酒的界面、合成、解锁与材料扣除见《调酒系统需求案》。
仓库只存放三类内容：售出用的酒、调酒材料、装备。
经济
货币是整数，初始 500。不能透支的花费，余额不足时按钮置灰。悬赏张贴不扣 G，不参与失败校验。
收入有两项：酒水付费（点单即入账）与悬赏奖励（入账时点见悬赏子案）。酒水营业中点到多少就是多少，不扣成本。
支出有两项，在每天 0:00 按这个顺序扣除：
营业日成本：按本日点单杯数计算。
酒保工资：暂定每营业日 20。	
失败：0:00 先汇总本日已入账收入，再扣成本，再扣工资。若余额 < 0，记为 0 并游戏结束；余额 = 0 不结束，进入下一营业日。
游戏结束后，依据酒馆总流水评分。总流水口径与评分表不在本篇，见结算系统。
